# 01 · 需求 / 活 PRD 〔本项目活记忆 · AI 维护〕

> **作用**:这是本项目唯一的需求文档。所有新功能、缺陷、技术债都追加到这里,不要另起多个 PRD 文件。
> **更新时机**:每次有新需求、需求变更、验收标准变化时更新。

---

## 1. 需求来源

| 类型 | 来源 | 进入方式 |
|---|---|---|
| 功能需求 Feature | 用户 / 老师 / 产品 / 客户 | 写成用户故事 |
| 缺陷 Bug | 测试 / 线上日志 / 用户反馈 | 写复现步骤和期望结果 |
| 技术债 Tech Debt | 开发 / Review / CI/CD 故障 | 写影响和修复目标 |

---

## 2. Issue 生命周期

| 阶段 | 状态 | 动作 |
|---|---|---|
| 提出 | Open | 写清场景、目标、验收标准 |
| 排期 | Backlog / Todo | 决定优先级和负责人 |
| 开发 | In Progress | 从 main 开 feature 分支 |
| 评审 | In Review | 提 PR,等待 CI 和 Review |
| 合并 | Done | PR 合并 main,自动关闭 Issue |
| 验收 | Verified | 按验收标准确认 |

**追踪规则**:分支名带 Issue 号,PR 描述写 `closes #<编号>`。

## 4. 需求清单

### US-1 初始化项目工程化与 CI/CD · 状态: Backlog

作为 **项目开发者**,
我想要 项目具备基础工程结构、测试、CI 与 CD,
以便 后续每次开发都能自动检查并自动部署。

验收标准:
- AC1: 从 `main` 开 feature 分支完成初始化,不直接 push main。
- AC2: PR 触发 CI,至少包含格式检查、静态检查、单元测试、构建检查。
- AC3: CI 全绿后合并 main。
- AC4: 合并 main 自动触发 CD,部署后健康检查通过(`/_stcore/health` 返回 `ok`)。
- AC5: 完成后更新 `standards/PROGRESS.md`。

技术备注:
- 端口固定主机 8888 → 容器内 8501;镜像/容器名 `banksys_szai4`。

### US-2 数据分析交互页面 · 状态: Backlog

作为 **银行营销分析师**,
我想要 在网页上交互式探索训练数据(概览、分布、类别-目标交叉、筛选联动),
以便 理解数据特征与认购行为的关系,支撑后续建模与业务判断。

验收标准:
- AC1: Given 打开应用首页,Then 展示数据概览(行数、列数、目标 `subscribe` 的 yes/no 占比)。
- AC2: Given 选择类别特征(如 job/marital)或调整数值特征范围,Then 图表随之联动更新,无需刷新页面。
- AC3: Given 任意单类别特征,Then 展示该特征各取值下的认购占比(交叉分析图表)。
- AC4: Given 数值特征选择,Then 展示其分布图(直方图)。
- AC5: Given 全部交互操作,Then 不依赖外部网络/服务,纯本地数据即可运行。
- AC6: 页面核心逻辑(过滤、聚合、统计)有单元测试覆盖。

技术备注:
- 图表使用 Plotly,嵌入 Streamlit;数据加载与过滤逻辑写成纯函数便于测试。

### US-3 离线训练与模型产物 · 状态: Backlog

作为 **数据科学家/开发者**,
我想要 一条命令从 `data/train.csv` 完成训练、评估并导出模型产物,
以便 用训练好的模型支撑在线预测,且训练结果可复现、可回归。

验收标准:
- AC1: Given 运行 `python -m ml.train`,Then 在 `models/` 生成模型产物(`.joblib`)与评估报告(含 holdout AUC/F1 等指标)。
- AC2: Given 训练完成,Then 对 `data/test.csv` 生成预测结果文件(CSV,含 `id` 与 `subscribe` 预测)。
- AC3: Given holdout AUC < 0.80,Then 训练脚本以非零退出码失败(CI 红灯),不产出可部署产物。
- AC4: Given 固定随机种子,Then 连续两次运行产出相同评估指标(可复现)。
- AC5: 数据加载、预处理、pipeline 构建均有单元测试;训练/预测共用同一预处理,保证在线与离线特征一致。

技术备注:
- 使用 scikit-learn;`models/` 不进 Git,Docker 构建时运行训练生成模型。

### US-4 在线预测系统 · 状态: Backlog

作为 **银行营销人员**,
我想要 在网页上通过点选/下拉/数字输入客户信息,立即得到该客户是否认购的预测,
以便 在联系客户前判断优先级,提高营销效率。

验收标准:
- AC1: Given 打开预测页,Then 页面提供全部 21 个特征的输入控件:类别特征用下拉/单选(选项与训练数据取值一致),数值特征用数字输入。
- AC2: Given 填写完整输入并点击预测,Then 展示认购概率、是否认购结论(阈值 0.5)与模型训练时间/版本。
- AC3: Given 模型文件缺失,Then 页面给出明确提示(引导先运行训练),而不是崩溃。
- AC4: Given 非法输入(如越界值、缺失必填项),Then 页面给出可理解的错误提示,不崩溃。
- AC5: 预测核心逻辑(输入校验、特征编码、概率输出)有单元测试覆盖。

技术备注:
- 输入控件取值硬编码会与训练数据漂移,选项应从训练数据/预处理器的已学类别动态生成(或固化在产物中)。

### US-5 预测界面中文化 · 状态: Backlog

作为 **银行营销人员**,
我想要 在线预测页的字段名与选项全部显示中文,
以便 不懂英文也能快速、准确地填写客户信息。

验收标准:
- AC1: Given 打开在线预测页,Then 全部 21 个字段显示中文名称(如 job→职业、marital→婚姻状况)。
- AC2: Given 展开任一下拉框,Then 选项显示中文(如 admin.→行政、jan→1月),**内部取值仍为英文**,模型预测不受影响。
- AC3: Given 输入非法值触发校验提示,Then 错误信息中的字段名为中文(附英文原名便于对照)。
- AC4: 中文字典模块(字段/选项映射)有单元测试。
- AC5: Given 打开数据分析页,Then 特征选择器、图表标题与刻度同步显示中文。

技术备注:
- 用 `st.selectbox(format_func=...)` 做「英文取值 + 中文显示」,不改变模型输入。
- 图表刻度用 `fig.update_xaxes(ticktext=..., tickvals=...)` 中文化,底层数据仍为英文取值。

## 5. 非功能需求

- **安全**:密钥只进 Secrets,不进 Git。
- **可维护**:一需求一小 PR,避免大爆炸式提交。
- **可测试**:核心逻辑必须有单元测试,覆盖率 ≥ 80%。
- **可部署**:部署后必须有健康检查(`/_stcore/health`)。
- **数据与产物**:`data/` 公开教学数据进 Git;`models/` 产物不进 Git,可重复生成。
- **端口**:主机 8888 固定;容器内 8501。
